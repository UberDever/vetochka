## Nyad rename (decision, from ChatGPT dialogue "Naming a node nyad", exported to dialogue/)
- Deltas renamed to nyads; sigil `^` -> `~`; `~` removed from prefix operators.
- Form: `~[]`, `~[x]`, `~[x, y]`; `~[x, y, z]` is a syntax error. Arity structural, no numbers.
- `~` and `$` are analogous sigil heads: entry points into restricted syntactic families. Whitespace after `~` immaterial.
- Applied to `docs/new_spec/02_syntax.md` and `03_v0.md`; old `docs/spec/`, dialogue, memory left in caret notation as history.

## ADR 1: adjacency-classified operators (accepted)
- Lexer classifies operator runs: glued-to-identifier = identifier continuation; glued after literal/`)`/`]` = error; glued-right = op_prefix; else op_infix. Trivia breaks gluing.
- Grammar gets op_infix/op_prefix terminals; closed prefix_operator list removed — any run can be prefix. `x -y`, `! x`, `1-2`, `f(x)-y` all errors; `!!x` is one operator `!!`.
- Void if juxtaposition application is ever added. See dialogue/adr-1-operator-adjacency.md.

## G1/G2 rulings + obs (user)
- identifier_continue loses `=` and `|` (so `x = y` needs spaces; `|` freed up). Runs glued after identifier (`x:=`, `x=`) = error; lone `:` label is the only glued exception and MUST be glued (`f x : y` error).
- No passing sole `$` as identifier — it's a quasiid by grammar placement, must bind a label next. Operator-as-datum = desugared form (`{op}` bytes / built term), by design.
- User pondering k-v/label syntax: convention head (`k-v x: 1 ...`) vs reserved `|` sigil for k-v lists; open dialogue.

## C6 + R1: labeled expressions and glued attachment (accepted)
- `label: expr` is a first-class labeled expression, legal as entry in lists/blocks/groups; k-v lists are just `[x: 2, y: 4]` — no `|` sigil, no new tokens. Payload is tight; nesting needs parens.
- R1: tight postfixes (`.name`, `()`, `[]`, `{}`) must be glued (`f (a)` error, catches missing commas); spacing before loose postfixes (labels, do-end) immaterial. No juxtaposition anywhere; ADR-1 intact.
- Five application shapes: `f(args)`, `f[list]`, `f{bytes}`, `f x: v`, `f do end`. See dialogue/labels-kv.md.

## Block promotion (accepted)
- Bare `do...end` is now a standalone entry lowering to inert `[{:block}, ...]`; entry ::= labeled_expression | block_argument | expression. Rule 7/7a split mirrors 6/6a. `f do a end` == `f(do a end)` in lowered form.

## Group erasure + delimiter gluing in grammar (accepted)
- Rule 4 changed: `(entry) -> entry`; no `[{:group}]` marker — parens are purely syntactic (attachment/nesting), grouping-as-datum is a list. Otherwise Rule 3 could observe parenthesization.
- Gluing moved from prose into token classes: `g_lparen`/`g_lbracket`/`g_string`/`g_dot` (glued to expression-ending token), `g_colon` (glued to label word); free `.`/lone `:` errors. `~ [x]` stays legal automatically (`~` is not an expression ender).
- Open: sole `$` — grammar-enforce label (a) vs opcode trap (b).

## Sole-$ ruling (accepted, option a)
- `$` removed from primary; `dollar_expression ::= $ g_lbracket comma_list "]" loose_postfix* | $ loose_postfix+`. Bare `$` unparseable; namespaced `$[ns, op]` alone is legal (curried opcode initial state). `$` dropped from ASI expression-ending tokens.

## Dollar reshaped; a-rules dropped (supersedes sole-$ entry above)
- ~~dollar_expression branch~~ superseded: `$` is now a primary `opcode ::= $ ( g_lbracket comma_list "]" | labeled_expression )` — sigil grabs its selection, rest is ordinary postfix machinery. Bare `$` unparseable by construction.
- Lowering rules 6a/7a removed as derivable; one line instead: loose postfix lowers as plain application of its datum.
