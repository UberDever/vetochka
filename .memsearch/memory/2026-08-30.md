## Nyad rename (decision, from ChatGPT dialogue "Naming a node nyad", exported to dialogue/)
- Deltas renamed to nyads; sigil `^` -> `~`; `~` removed from prefix operators.
- Form: `~[]`, `~[x]`, `~[x, y]`; `~[x, y, z]` is a syntax error. Arity structural, no numbers.
- `~` and `$` are analogous sigil heads: entry points into restricted syntactic families. Whitespace after `~` immaterial.
- Applied to `docs/new_spec/02_syntax.md` and `03_v0.md`; old `docs/spec/`, dialogue, memory left in caret notation as history.

## C6 + R1: labeled expressions and glued attachment (accepted)
- `label: expr` is a first-class labeled expression, legal as entry in lists/blocks/groups; k-v lists are just `[x: 2, y: 4]` — no `|` sigil, no new tokens. Payload is tight; nesting needs parens.
- R1: tight postfixes (`.name`, `()`, `[]`, `{}`) must be glued (`f (a)` error, catches missing commas); spacing before loose postfixes (labels, do-end) immaterial. No juxtaposition anywhere; ADR-1 intact.
- Five application shapes: `f(args)`, `f[list]`, `f{bytes}`, `f x: v`, `f do end`. See dialogue/labels-kv.md.

## Block promotion (accepted)
- Bare `do...end` is now a standalone entry lowering to inert `[{:block}, ...]`; entry ::= labeled_expression | block_argument | expression. Rule 7/7a split mirrors 6/6a. `f do a end` == `f(do a end)` in lowered form.

## Group erasure + delimiter gluing in grammar (accepted)

## Binder-boundary axiom (user insight, resolves observation fork)
- A ruled: callee-dependent raw arguments accepted by design; the raw-taking opcode named `$form` (continuity with historical {form}); v0 is target/substrate language, not production surface.
- Axiom: binders are the sole nonlocality (side effects aside); E is a property of binder nodes alone, fragments are pure trees.
- B1 dissolves: identifiers are written references; observation follows them (bound -> value, unbound -> name). B2 resolves: closure pith = declarators + body syntax, no env slot; observation across a binder boundary is re-quotation by principle; duality holds everywhere else.

## TERM refined: machine cell vs value (user + agent)
- No substitution => every deferred evaluation pairs term with env: pending operands (callee-first retains operand with E-caller), opcode raw inputs. These TERMs are machine-internal (K/opcode state), never observable data.
- The only env-carrying VALUE is the closure (binder node). "TERM everywhere in the machine, TERM only at binders in the data." Observation sees values only, so the binder axiom holds; CESK deferral rules construct machine-TERMs, closure construction alone promotes one to a value.

## Code closures (ruled)
- An in-flight (partially applied) opcode value is exactly a closure — a "code closure": env-carrying value, pith shows syntax only (selected opcode + inputs as written), envs hidden.
- Precision (user): declarator inputs like `$fn: [x]` DECLARE x, referencing no outer binder — env pairing is only needed for retained inputs that can use outer bindings (raw $form payloads, computed declarators). Eager inputs are stored as values, no env.

## Architecture correction (user): phase-separated porosity
- vsystem is NOT v0-semantics-in-C. Stack: v0 machine -> vmeta (v0 is vmeta's executable substrate and internal implementation language, the only place v0 arises) -> vsystem compiler written in vmeta, integrated into vsystem -> emits separate ordinary C.
- Kell's dual-porosity question resolved by phase: internal porosity at build time only (vmeta/cells/observation), external porosity via the emitted C artifact. vsystem has no runtime reflection by design. C enters the reflective world as data (ABI/layout/header models in cells), never as a competing runtime.
