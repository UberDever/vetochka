# Raw-byte literal syntax

- Decision (user): use `~{...}` for raw bytes. Each byte uses two hexadecimal digits, with either letter case. Whitespace between byte pairs is optional.
- Examples (user+agent): `~{00 7f ff}` and `~{007fFF}` denote the same three bytes. `~{}` denotes empty bytes, distinct from `~`. Plain `{...}` remains a UTF-8 string.
- Grammar detail (agent): whitespace may also occur at either end, including newlines. Digits within a pair remain adjacent. The literal contains only complete byte pairs and whitespace.
- Parser consequence (agent): recognize `~{` as a byte-literal opener. It takes precedence over the former parse as a Nil term with a tight string application. `(~){text}` retains the explicit application form.
- Documentation (agent): `docs/new_spec/02_syntax.md` now includes literal examples, lexical grammar, content rules, and the disambiguation rule.
- Boundary (agent): parser and formatter implementation remain pending. The broader core and lowering rewrite follows the Nil/Pair/Bytes direction in 20260926-091318. No numeric byte encoding or tag layout was selected here.
