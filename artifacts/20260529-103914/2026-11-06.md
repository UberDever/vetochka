# Scratchpad: forcing a producer that returns executable syntax

- Scope (user): the Lisp comparisons in this discussion are comparisons, not a language design decision.
- Question (user): how does let forcing execute `parse_term` without also executing the application tree that parsing returns?

```vf
=[x: parse_term{{+}[2,3]}] do \[y] do {+}[x, y] end end
```

- Encoding qualification (user): the example does not require a string callee. An operation can use a tagged list such as `@[a-special-op] [{+}, ...]`.
- ~~Proposal (agent, unapproved): distinguish executing a term from returning a term to a pending continuation. `parse_term` returns its tree to the let-binding continuation. The continuation binds that result without submitting it for execution again.~~ Superseded for this example by the user's closure-based direction below (2026-11-06).
- Consequence of the proposal (agent): a returned term can have an executable application shape. Completion cannot mean that the returned tree contains no reducible application.
- Qualification (agent): completing one requested computation is not necessarily one reduction step. A producer can perform internal computation before returning its result.
- Open (agent): define this boundary consistently for native operations, user-defined producers, lambda substitution, and selected blocks. A parser-specific exception would not settle the general staging contract.
- Discriminating example (agent): should forcing the following wrapper produce the parsed tree in the same stage, or return its substituted body for another explicit stage?

```vf
=[x: (\[s] do parse_term(s) end){{+}[2,3]}] do x end
```

- Context (agent): `2026-10-23-anf.md` records the tentative distinction between returning a substituted closure body and entering it. `2026-10-26.md` distinguishes executing a block from returning it as data. The current execution section in `docs/new_spec/03_v0.md` does not yet settle the machine transitions.
- Boundary (agent): no evaluator was changed, and no new execution rule was approved. Binding semantics remain coordinated with 20241225-140425.

## Closure-based direction

- Direction (user, scratchpad): `parse_term` can return the parsed term inside `\[_] do thing end`. The ordinary lambda supplies quotation without a separate quotation form.
- Clarification (user): use `x()` to apply the returned lambda in the subsequent program:

```vf
=[x: parse_term{{+}[2,3]}] do \[y] do {+}[x(), y] end end
```

- Correction (agent): ordinary lambda construction and application suffice for the proposed wrapper. Pith extraction is not required for this use. The earlier return-protocol proposal is not the selected solution to this example.
- Boundary (user): the Lisp comparisons in the surrounding scratchpad remain comparisons, not additional language design commitments.
