# Vetochka before the devlog's 2026 entries (14.12.24 – 05.12.25)

The devlog has two 2024–2025 dates (`25.12.24`, `23.01.25`), both imported from the old project history.
Everything else from that period existed only in Git on the old branches listed in `history-recovery.md`.
This file restates it from the documents under `sources/` and from the code. Statements marked "intent" are
reconstructed from code and commit messages, not from written decisions.

## Original goal (`TODO.md`, 14.12.24 – 16.12.24)

Source: `sources/8ff2f02/TODO.md`, `sources/85d5881/TODO.md`.

- Requirements: a language based on tree calculus that compiles to C. The C output must be human-readable and
  maintainable. Metaprogramming lets the language act as a wrapper over C code. It provides no runtime, at least not
  as a built-in dependency.
- The "mighty preprocessor" plan (16.12.24): write a functional language over tree calculus, transpile embedded C to
  it, transform and partially evaluate it, then transpile back to C. The note calls this "ridiculously hard if done
  in full swing" but feasible for a subset of C, and names tagging and evaluation without interpretation as tree-
  calculus properties that help build the IR.
- The first tokenizer split on whitespace except inside `{}`. It "didn't work out"; richer tokenization was chosen to
  support levels of sugar. Encoding of lists, numbers and strings was assigned to the interpreter, not the tokenizer.
- The same goal reappears in the 2025 spec introduction (`../20261110-000001/spec/01_introduction.md`) and is
  reframed on 28.05.26 as a reflective, staged frontend for C.

## Grammar, December 2024 – February 2025

Source: `sources/8ff2f02/docs/grammar.md` (25.01.25), grammar section of `sources/84e6f93/docs/language.md` (16.02.25).

- Tokens: tree `^` (the first grammar, 20.12.24, also allows `Δ`), delimiters `()[],;`, strings, symbols. Numbers `0 | [1-9][0-9]*`.
- Strings: `{...}` with balanced braces, or `{{{...}}}`; "only data `}}}` is unrepresentable — fair enough".
- Comments went from `--` (26.12.24) to `#` (08.01.25) to `#` followed by mandatory whitespace (25.01.25).
- Intrinsics `#{name}` are byte sequences that communicate with the interpreter during bytecode execution (25.01.25).
- Lambda parameters are symbols prefixed by `\` or `λ` (14.01.25).
- Infix operators `+ - * /` were added on 21.12.24 and removed the same day ("don't need them for now").
  Application is left-associative juxtaposition, with optional parentheses (22.12.24).
- `;` equals a line break. Semicolon auto-insertion was deferred: on 07.01.25 the greedy application parser consumed
  the rest of a file, and the noted fix was explicit termination characters.
- Scope forms: `module {name} do ... end`, `scope {name}? do ... end`, `use {name} sym*`, `use {name} sym* in expr`
  (13.01.25 – 25.01.25). A statement or block form was rejected in favour of lists (25.01.25).

## Language levels (`docs/language.md`, 16.02.25)

Source: `sources/84e6f93/docs/language.md`.

The language is described as a tower where each level includes the previous one. Object algebras and nanopass
were named as formal options; a simple ontological layering was chosen as a reasoning aid without formal guarantees.

| Level | Adds | Bytecode | Evaluation |
| --- | --- | --- | --- |
| Vetochka 0 | `^` and application only | `NODE_TREE lhs rhs`, `NODE_APP` | the three tree-calculus rules, branch-first |
| Vetochka 1 ("with intrinsics") | lists, strings, numbers, intrinsics | `NODE_DATA n`, `NODE_EVAL n` | a 4th rule for `($ NODE_EVAL[n] [args...])` |
| Vetochka 2 ("λ") | abstraction | unchanged | unchanged |
| Vetochka 3 ("M") | module system | unchanged | unchanged |

This is the earliest form of the later v0/vf split and of the July 2026 layer tower.

## First pipeline: Python plus a C evaluator (December 2024 – February 2025)

Intent from code (`tokenizer.py`, `parser.py`, `semantics.py`, `backend.py`, `eval/`, `main.py`):

- Python tokenizer and parser. `saturate` and `strip` normalize the parse tree. `semantics.py` was planned to remove
  sugar down to scopes and `use`, after which a bytecode module would lower to tree calculus.
- Node encoding (24.12.24 – 10.01.25): one 64-bit word per node, a 2-bit tag `TREE | APP | DATA`, and two 31-bit
  relative child offsets. The Python encoder notes that it targets "a system language like C".
  The evaluator was moved to C89 (08.01.25) and called from Python through ctypes; a REPL followed (10.01.25).
- Planned "clamp" encoding (22.01.25): store `^^^` as the all-zero word, giving up index 0.
- Number encodings tested both as lists of small numbers (bytes) and as left-filled trees (`backend.py`).
- Tag `v0.1.0` (07.02.25): "Inital version, late to the party". Its README describes an interpreted functional
  language based on tree calculus: the smallest core possible with levels of sugar, a "somewhat esoteric" base
  calculus, and a sandbox for design ideas. The main application is a rich preprocessor or metalanguage for C
  (`sources/0999763/README.md`).

## Second evaluator: cells, stacks and natives (PR #2, 17.02.25 – 21.05.25)

Intent from `eval/*.c` on `feature/branch-first-eval-17.02.25` and `feature/native-eval-16.05.25`:

- 17.02.25: reimplemented as "eval for vetochka 0". The rules were first written with `,` as application:
  `^, z -> ^ z`; `^ y, z -> ^ y z`; `^ ^ y, z -> y`; `^ (^ x) y, z -> (y z)(x z)`; then triage rule 3a
  "baking the rules of triage into reduction itself".
- April 2025 memory model: 2-bit cell kinds `nil *`, tree `^`, reference `#`, packed 32 per word, and a separate
  payload table of 64-bit words keyed by cell index. A tree is stored in preorder; `^**` is a leaf.
  A native function is the cell pattern `##*` whose payload is a function pointer.
- References are second class: no reference to a reference (13.04.25). `#` became references only (18.04.25),
  and their payload untagged. On 20.05.25 every payload became a plain number with no tags.
- 18.04.25: application nodes were eliminated, "it is believed that we don't need it since we have computation
  stack". Evaluation used an apply stack, with a sentinel token for application, and a result stack.
- Rule table (15.04.25 – 30.04.25): saturation rules 0.a and 0.b build a stem or fork from an applied leaf or stem;
  rule 1 (`^ ^ y` applied → `y`), rule 2 (stem-left fork → `(x z)(y z)`), rules 3a/3b/3c (triage on the argument's
  shape), and rule 4 (a native applied to any value). The code notes which match shapes "cannot occur in tree
  calculus" and that the unified rule naming made names clash.
- Tests: Python was dropped for pure C (28.04.25). Test cases are JSON snapshots of the whole machine
  (cells string, payload words, apply and result stacks) validated by `state_schema.json`
  (`sources/ee4712d/eval/`). A requested improvement was step-by-step expected states with step counts.
- Natives (16.05.25 – 21.05.25): a registry of named natives with `type.integer` and `type.list` tags, and values
  tagged as `^ T [payload]`. `io.print` prints an integer or a list of integers as characters, "no unicode for now".
  `b9c710d` "My first hello"; tag `v0.2.0` "native calls".
- Commit messages record AI assistance: "AI helped to write this code" (12.04.25), then "Completely rewritten the
  goddamn allocator, AI is not a silver bullet" (13.04.25).
