### 20.10.26
- (#process #decision) Records. Consolidate design work into fewer broad subjects because scattered, repetitive records consume attention. Preserve decisions and open questions without treating reorganization as approval of language proposals.
- (#syntax #decision) Adjacency. Express adjacency through `NO_WS` and `WS` grammar constraints after ASI, replacing classified operator/delimiter terminals. Infix operators require trivia on both sides, including after `end`; comments count as trivia. Maximal matching remains: `x-y` is one identifier and `!!x` has one prefix operator. Tight postfixes touch receivers and labels touch colons. `do:` and `end:` remain labels. See `artifacts/20241220-144435/2026-10-20.md`.
- (#syntax #question) Floats. Add floating-point syntax to the shared grammar. Decimal and exponent forms are undecided. Keep source notation separate from runtime representation; the initial runtime requirement remains i64.
- (#encoding #proposal) Wrappers. Explore Jay-style transparent wrappers for values and metadata entries. Desired example: `getTag(an_int)` yields `[tag: {:i64}, meta: []]`, while `untag(an_int)` yields `{1234}`. A tagged two-element list can represent a property entry. Bare descriptor schema, native payload observation, and recursive tagging remain unspecified.
- (#encoding #experiment #evidence) Tagging. A pure triage scratchpad reports 644 bounded forwarding/projection checks and concrete tagged-integer projections. Vetochka's distribution rule differs from Jay's, so use the local derivation. This establishes reductions for the constructed wrappers, not full-machine equivalence, effect ordering, native piths, or a production `tag` factory. See `artifacts/20260926-091318/2026-10-20.md`.
- (#encoding #question) Properties. Decide whether k-v collections are property lists, association lists, maps, or another model. Specify key equality, duplicate keys, ordering, missing keys versus empty/default values, and updates. Tagged properties are ordinary data; attachment alone neither validates a type nor selects execution behavior. Hidden interning must not make equal string keys depend on allocation.
- (#machine #decision) Parsed-code. `parse_term` preserves ordinary applications as inert syntax, allowing transformations such as replacing `print(x)` with `io.print(x)`. Executing a chosen root is separate. A confluence argument that first reduces the inspected source application assumes an execution step that parsing does not perform.
- (#machine #experiment #evidence) Interpreter. A closed interpreter encoded in pure triage reportedly passes eleven result/quotation round trips and exhausts a bounded run on divergence. It preserves raw operands and inspects only their roots. Names, native piths, blocks, and effects are absent; this is an experiment, not the selected runtime or a proof of the staging contract. See `artifacts/20260926-091318/exec.md`.
- (#encoding #syntax #decision) Annotation. `@[...] expression` denotes tagging semantics directly. Do not lower through a shadowable variable named `tag`. `getTag` and `untag` should be definable in v0; the particular tagging construction still needs selection and implementation.
- (#host #proposal) Bootstrap. Consider supplying a lookup function alongside a k-v namespace, tentatively `$[fn: [get, builtin]] do ... end`. Putting the accessor only inside its own namespace does not bootstrap access to it. Reconcile this proposal with opcode and parameter syntax before choosing an import or entry interface.
- (#binders #proposal) Raw-inputs. Consider replacing `$form` with an ordinary closure whose body a consumer can inspect or invoke under captured bindings. An older zero-parameter thunk example conflicts with the draft rule that an empty parameter list executes on saturation; resolve that conflict before using empty-parameter closures as quotations.

### 23.10.26
- (#machine #decision) Basis. Move evaluation to lambdas, retaining construction and structural inspection as the useful principles from triage calculus. Remove primitive rules 1 and 2 rather than preserving the whole calculus as the evaluator. At this stage construction from rule 0 is still retained; exact replacement rules and names require design.
- (#syntax #encoding #decision) Applications. Replace mandatory `{@}` application records with tagged forks containing recursively lowered function and operand. Parenthesized, list, string, label, and block applications retain nested unary application structure and occurrence metadata. The VM instruction pointer selects when the representation is executed. This syntax/lowering decision does not settle the tagging mechanism or implement execution. See `artifacts/20241220-144435/2026-10-23.md` and `artifacts/20260926-091318/2026-10-23.md`.
- (#encoding #decision) Custom-tags. Assess a Vetochka-specific tagging mechanism instead of directly adopting Jay's construction. The goal is application transparency by construction, useful structural inspection, and composable annotations. `@[a] @[b] x` combining roughly as `@[[a, b]] x` is a tentative example, not a selected composition law.
- (#machine #binders #decision) Forcing. Lambdas capture environments; bindings explicitly force computations. Do not normalize `f(g(x))` by silently forcing `g(x)`: that would change the intended raw-operand behavior. Lambdas and bindings belong in the executable core; assess other ANF forms individually rather than importing an entire call-by-value language.
- (#machine #proposal) ANF. A-normalization can make intermediate computations and their order explicit, but represented application trees can themselves be values. A normalizer must distinguish executable syntax from inspected data. Neither the ANF paper's equivalence result nor its atomic/compound partition proves preservation of Vetochka's reflective observations. No elaborator or VM adaptation is implemented. See `artifacts/20260529-103914/2026-10-23-anf.md`.
- [ ] (#binders #question) Binding. Assess `=[a: 12, b: f()] do ... end` against earlier sequential and recursive let clauses. Specify evaluation order, scope, computation positions, dynamic declarators, currying, saturation, and shadowing. Closure application tentatively produces a body with bindings installed rather than immediately executing it; that distinction still needs an exact contract.

### 26.10.26
- (#machine #decision) Lambda-core. Remove primitive rule 0 as well as rules 1 and 2. Lambda application can express its construction behavior, for example `(\[x] do ~[x] end)(~)`. Retain trees and structural triage as design principles, not the original evaluator. Lowering every executable form to applications is proposed; callees, encodings, and execution contracts are not yet specified.
- (#machine #decision) Blocks. Executing a nonempty block forces entries in source order, discards intermediate results, and returns the last result. Constructing or returning the block as data does not execute it. Empty-block results and the sequencing mechanism remain open; this does not select binding-based sequencing over a dedicated block operation.
- (#machine #decision) Triage. Inspect the subject without evaluating applications or recursively forcing children. Follow bound identifiers to their values; inspect unbound identifiers as names, although executing an unbound identifier is an error. In the then-current leaf/stem/fork model, bind neither child, the left child, or both children respectively. This contract needs implementation independently of surface syntax. See `artifacts/20260529-103914/2026-10-26.md`.
- [ ] (#machine #binders #question) Dispatch. Specify triage/binding lowering without implicit operand forcing, whether selection enters a clause or returns its bound body, and shadowing when a selected clause has no binding for a triage name. Define errors, `exec` stepping versus run-to-result, the driver, and completion. Retain the tail-call and native-trampoline constraints while redesigning control.

### 07.11.26

Bytes are directly observable payloads, distinct from Nil, rather than hidden storage behind a claim that everything decomposes into homogeneous nyads.
