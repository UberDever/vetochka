# The core: v0

`Vetochka` is a layered language: you have an executable core and everything else that is built around it.
This section describes this core called `v0`.

Whole `v0` and, by extension, `vetochka` built from the primitives: `leaf`, `fork` and `blob`.
There is nothing more than that, everything else is encoding conventions.

## Syntax

The complete syntax is located in `vf:TODO:` section. Following
syntax examples should give a clear picture for the core subset.
We introduce it as the notation to describe further subsections.

```
~                       ;; a leaf, a nil, a unit, the one and only
~[x, y]                 ;; a fork, a pair, a cons cell
~{aBCd e fg}            ;; a blob, bytes, a payload, encoded using hex notation with whitespace
{Hello Larpers💯!}     ;; a second form of bytes, utf-8 payload inline
```

Proper lists are fundamental enough to have their own shorthand:

```vf
[]     == ~
[x]    == ~[x, ~]
[x, y] == ~[x, ~[y, ~]]
...
```

## Tagging

Every distinct non-primitive value in the language is tagged and every such value is a
tree. A tag is a list at the start of a value (a head), with a specific structure.

Rich syntax of `vetochka` is lowered to tagged trees and lowering rules are decribed in
`vf:TODO:` section.
All these rules use a tagging format defined below. We use informal placeholder-driven
notation that should be clear by its usage context.

```
tag = [<kind>, <source-id>, <byte-offset>, <byte-len>, <k-v-meta>*]
kind =
    | {$}
    | {:binder}
    | {:closure}
    | {:triage}
    ...

source-id =
    | ~
    | a-string
    | a-buffer
    | a-port

byte-offset = a-i64
byte-len = a-i64
k-v-meta = [{:kv}, a-string, a-value]
```

When `byte-len` is 0, a value should be considered runtime-built or synthetic.

Specific `a-*` value kinds and their structure are described in the
`std:TODO:` section.
